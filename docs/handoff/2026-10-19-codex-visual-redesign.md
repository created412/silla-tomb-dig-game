## 0. 한 줄 요약

로직은 다 되어 있고 테스트도 통과하는데, **화면이 노잼이다.** 단색 사각형 격자, 이모지 글자 하나뿐인 캐릭터, 노란 막대로 그린 금관. 이걸 "아이가 남에게 보여 주고 싶은 화면"으로 다시 만드는 것이 이번 일이다. 발굴 로직·입력·테스트는 손대지 않는다.

- 저장소: https://github.com/created412/silla-tomb-dig-game · 브랜치 `prototype/dig-0` (푸시하면 1~2분 뒤 Pages에 자동 반영)
- 게임 계획서: `docs/plans/01-초등용-게임계획서.md` (특히 1장 핵심 경험, 4장 토우 캐릭터, 6-1 3층 뚫기, 11장 화면·분위기)

## 1. 이 게임이 뭔가

초등 5~6학년(10~12세)이 태블릿으로 하는 신라 고분 발굴 게임. 기획자는 아빠 역사교사이고, 학교 수업(20분)과 집에서 혼자 하기 둘 다 목표다. 0차 시제품은 그중 "손맛" 하나만 검증한다.

흐름: 제목 → 🐸🐍 만담 4줄(wake) → 흙 문지르기 → 돌 톡톡 → 나무 붓질 → 금관 드러남 → 만담 4줄(found) → "또 파고 싶어?"

검증 질문은 하나다. 아이가 끝나고 "응, 또!"를 누르는가. 그래서 화면이 재미없으면 시제품 목적 자체가 깨진다.

## 2. 지금 화면이 왜 노잼인가 (진단)

실제로 열어 보고 판단한 것:

1. **격자가 보인다.** 12×7 셀이 단색 사각형이라 "땅을 판다"가 아니라 "엑셀 칸을 지운다"로 느껴진다. 셀 경계를 숨기고 흙·돌·나무가 이어진 한 덩어리로 보여야 한다.
2. **캐릭터가 없다.** 🐸🐍는 대사 상자 왼쪽에 이모지 글자 하나다. 몸도, 표정도, 움직임도 없다. 계획서의 핵심 매력(티격태격 토우 콤비)이 화면에 0% 반영됐다.
3. **금관이 노란 막대 도형이다.** `renderer.js`의 `drawCrown`. 임시라고 적어 뒀지만 아이 눈에는 그냥 못생긴 그림이다.
4. **"찾았다" 장면이 약하다.** 흰 플래시 0.4초 + 어두운 배경 + 도형 확대뿐. 계획서는 이 장면을 "아이가 남에게 보여 주고 싶은 장면"으로 요구한다.
5. **피드백이 빈약하다.** 먼지는 4px 네모, 반짝임은 희미한 원, 흔들림 8px. 돌이 깨질 때 금이 가는 중간 단계가 안 보인다.
6. **제목·마무리 화면이 글자와 버튼뿐이다.** 세계관을 암시하는 그림이 없다.
7. **HUD가 사무적이다.** 흙/돌/나무 진행 바 3개. 아이용 게임 느낌이 아니다.

소리(`sfx.js`, 합성음)는 이번 범위에 넣지 않아도 되지만 연출에 맞춰 바꿔도 된다.

## 3. 디자인 방향 (계획서에서 확정된 것)

- **색**: 흙빛·청록·금색. 무덤 안은 어둡지만 **무섭지 않게**, 틈으로 금빛이 새어 나오는 "보물 느낌".
- **토우 캐릭터**: 신라 토우(손가락만 한 투박한 흙 인형, 작은 눈, 뚱한 표정)를 바탕으로 한 **창작 캐릭터**. 친근한 그림체, 둥글고 납작하게. 특정 무덤 출토품이라고 주장하지 않는다.
  - 🐸 개구리: 겁 많고 말 많음. 파는 담당. 놀라면 눈이 커지고 팔을 휘젓는다.
  - 🐍 뱀: 느긋하고 능청. 반쯤 감은 눈, 혀 날름. 뭐든 "내 거야".
  - 실제 신라 토우에 뱀이 개구리를 쫓는 장면이 있다. 이 관계가 만담의 뿌리다.
- **유물(금관)은 캐릭터화 금지.** 얼굴을 붙이거나 귀엽게 바꾸지 않는다. 사실적인 도판으로 그린다. 천마총 금관 형태: 出자 모양 세움 장식 3개 + 뒤쪽 사슴뿔 장식 2개 + 금 띠 + 곡옥(굽은 옥)과 달개(둥근 금판)가 매달림. 사진은 저작권 확인 전이라 쓰지 말고 **벡터/캔버스로 직접 그린 도판**으로.
- **틀리는 게 더 재미있다.** 연타해서 돌이 와르르 다시 쌓이는 것, 세게 문질러서 🐸가 "살살!" 하는 것은 벌이 아니라 개그다. 연출도 그렇게(과장되게, 손해 없이).
- **금지**: 피, 해골, 유령, 무덤·장례 조롱. 웃음은 토우 둘의 관계에서만 나온다.
- **오늘날 초등 취향**(기획자 요구): 짧고 과장된 리액션, 둥근 캐릭터, 화면이 즉각 반응하는 느낌. 스크린샷 찍어 친구에게 보여 주고 싶은 순간이 최소 하나 있어야 한다.

## 4. 해야 할 일 (우선순위 순)

### P1. 발굴 화면을 "땅"으로 만들기

- 셀 경계를 없앤다. 흙·돌·나무 각 층을 오프스크린 캔버스에 텍스처로 한 번 그려 두고, 각 셀의 잔량(0~1)을 **노이즈 마스크나 가장자리가 불규칙한 구멍**으로 깎아낸다. 지금처럼 셀 전체 알파를 낮추면 안 된다.
- 파인 곳에 깊이감(안쪽 그림자, 테두리 하이라이트).
- 돌: `rock[i]`가 1 → 0.66 → 0.33으로 줄 때 **금이 가는 단계**가 보여야 한다. 깨질 때 돌 조각 파티클.
- 나무 층 아래 금관 셀에서 `glimmered`가 켜지면 **틈 사이로 금빛이 새어 나오는** 연출(지금보다 훨씬 강하게, 맥동).
- 먼지·조각 파티클을 제대로. 크기는 CSS px 기준으로 계산할 것(현재 디바이스 px라 고해상도에서 절반 크기).
- 돌 연타 "와르르"는 화면 흔들림 + 돌이 위에서 다시 쏟아지는 애니메이션.

### P2. 토우 캐릭터를 화면에 세우기

- 🐸🐍를 **그림 캐릭터**(SVG 또는 캔버스 벡터)로. 발굴 화면 한쪽(예: 격자 아래 왼쪽·오른쪽)에 서 있는다.
- 대사 상자를 **말풍선**으로 바꾸고 말하는 쪽 캐릭터에서 꼬리가 나오게.
- 말할 때 몸이 살짝 통통 튀고, 이벤트별 표정:
  - `tooHard` → 🐸 눈 커지고 팔 휘젓기
  - `collapse` → 🐍 한숨, 🐸 머리에 돌 하나 맞기
  - `glimmer` → 둘 다 눈 반짝
  - `artifactRevealed` → 둘이 금관 쪽으로 달려옴
- 평소 idle에도 눈 깜빡임·호흡 정도의 미세 움직임.

### P3. "찾았다" 장면

2~3초짜리 연출. 순서 제안: 마지막 나무 조각이 걷힘 → 틈에서 빛 터짐 → 화면 어두워지며 금관이 떠올라 확대(반짝 파티클) → 🐸🐍 뛰어들어옴 → 만담 시작. 이 장면 정지 화면이 **스크린샷 찍고 싶은 화면**이어야 한다. 현재 `main.js`의 `onArtifactRevealed`(FOUND_PAUSE_MS 300)와 `renderer.drawCrownBig`이 그 자리다.

### P4. 제목 화면과 "또 파고 싶어?" 화면

- 제목: 무덤 봉분 실루엣 + 흙 속에서 🐸🐍가 빼꼼. 버튼 하나 "파러 가자!"는 유지.
- 마무리: 찾은 금관을 배경에, 🐸🐍가 "응, 또!"를 가리키는 식의 유도. 버튼 눌림 손맛(바운스).

### P5. HUD

진행 바 3개 대신 **땅 단면 아이콘**(흙/돌/나무 세 층이 위에서부터 깎여 나가는 세로 단면) 하나로. 안내 문구(`hint`)는 유지하되 캐릭터 말풍선이나 아이콘으로 통합해도 된다. 문구 자체는 `hud.js`가 만들며 테스트가 있으니 텍스트는 바꾸지 말 것.

### 선택

- 한글 둥근 글꼴(Google Fonts의 Jua, Gaegu, Do Hyeon 등) 도입 가능. 시스템 글꼴 폴백 필수.
- `sfx.js` 합성음을 연출에 맞게 조정.

## 5. 지켜야 할 제약

**기술**
- 바닐라 ES 모듈 + Canvas 2D + CSS. **빌드 없음, npm 의존성 없음.** GitHub Pages 정적 호스팅이라 모든 경로는 상대 경로(`src/…`, `assets/…`). 절대 경로 `/…`는 하위 주소에서 깨진다.
- 외부 로딩은 Google Fonts만 허용. 저작권 불명 이미지 금지. 그림은 직접 그린 SVG/캔버스 또는 CC0만.
- 태블릿 60fps 목표. 84셀을 매 프레임 다시 그리니 텍스처는 오프스크린 캔버스에 캐시하고, 파티클 수를 제한한다.
- 가로 태블릿 + PC 마우스 기준. 세로 휴대폰은 범위 밖. DPR은 2까지 쓴다(`main.js` resize).
- 터치 타깃 44px 이상, 본문 글자 20px 이상. 색 외에 테두리·글자로도 구분(접근성).
- 안드로이드 주소창 때문에 하단 말풍선이 잘릴 수 있다. `100vh` 대신 `100dvh`(폴백 포함)로 바꿔도 좋다.

**손대도 되는 파일**
- `prototype/src/renderer.js` (전면 재작성 가능), `prototype/style.css`, `prototype/index.html`
- `prototype/src/main.js` — 연출 타이밍·이벤트 연결 부분. 단계 전환 로직(title→wake→dig→found→again)과 `localStorage` 기록은 유지.
- `prototype/src/lines.js` — 대사 추가·수정 가능. 한 줄 40자 이내, 아이 말투 반말, 유물 조롱 금지.
- `prototype/src/sfx.js`
- 새 파일 추가 환영: `prototype/src/characters.js`, `prototype/assets/*.svg` 등.

**손대지 말 것**
- `prototype/src/dig-model.js`, `grid.js`, `input.js`, `dialogue.js`, `hud.js`, `prototype/tests/*`
- 손맛 수치는 검증 대상이라 그대로: 흙 셀당 600ms, 돌 3탭(0.34/탭), 4연타 250ms 이내면 와르르, 나무 셀당 900ms, 붓 속도 0.6 CSS px/ms 초과면 tooHard(1초 쿨다운). 바꿔야 한다고 판단되면 바꾸지 말고 이유를 PR에 적는다.
- `npm test`(33개)는 끝까지 통과해야 한다.

## 6. 연출을 붙일 수 있는 지점 (계약)

`input.js`가 `main.js`로 올려 주는 것. 연출은 전부 여기에 붙인다.

| 콜백/이벤트 | 뜻 | 페이로드 |
|---|---|---|
| `onTouchCell(cell)` | 손이 닿은 셀 | 셀 인덱스 |
| `onRub(cell)` | 흙이 실제로 깎였음 | 셀 인덱스 |
| `onBrush(cell)` | 나무가 실제로 깎였음 | 셀 인덱스 |
| `onRockDrag(cell)` | 돌 위를 40px 이상 문지름 (헛손질) | 셀 인덱스 |
| 이벤트 `chip` | 돌을 한 번 두드려 깎임 | `{type, cell}` |
| 이벤트 `rockBroken` | 돌이 완전히 깨짐 | `{type, cell}` |
| 이벤트 `glimmer` | 금관 셀의 돌이 깨져 금빛이 새기 시작 (셀당 1회) | `{type, cell}` |
| 이벤트 `collapse` | 연타로 돌이 다시 쌓임 | `{type, cell}` |
| 이벤트 `tooHard` | 붓질이 너무 셈 | `{type, cell}` |
| 이벤트 `artifactCell` | 금관 셀 하나가 완전히 드러남 | `{type, cell}` |
| 이벤트 `artifactRevealed` | 금관 6칸 전부 드러남 → found 단계 | `{type}` |

상태 객체(`state`, 읽기 전용으로 쓸 것): `cols` 12, `rows` 7, `soil`/`rock`/`wood` Float64Array 잔량 0~1, `artifactCells` Set(39~44, 4행의 3~8열), `glimmered` Set, `revealed` Set, `done`.
레이아웃(`layout`): `{cell, x0, y0, cols, rows}` 캔버스 px 단위. 셀 사각형은 `cellRect(layout, i)`.
`topLayer(state, i)`로 셀의 맨 위 층('soil'|'rock'|'wood'|'floor')을 알 수 있다.

현재 렌더러 인터페이스(`main.js`가 호출): `createRenderer(canvas)` → `{ draw(state, layout, tMs), drawCrownBig(scale, tMs), addDust(cell, layout, tMs), shake(ms, tMs), flash(ms, tMs) }`. 바꿔도 되지만 `main.js`의 호출부를 같이 고칠 것.

대사 큐: `createDialogue(LINES)` → `play(id)`, `next()`, `current()`, `isPlaying()`, `playIfIdle(id)`. 반응 대사(`playReaction`)는 2초 뒤 자동으로 사라지고, 만담(`playTalk`)은 탭으로 넘긴다. 이 구분은 유지.

## 9. 알려진 미처리 항목 (같이 고쳐도 됨)

- `100vh` → 안드로이드 주소창에 하단이 가림 (`100dvh` 권장)
- 먼지 파티클 크기가 디바이스 px 기준 (고해상도에서 절반)
- 반짝임 그라데이션이 셀 왼쪽·위로만 번짐
- `drawCrownBig(1.6)`의 확대 배율이 실제로는 약 1.2배
- iOS에서 길게 누르면 텍스트 선택이 뜸 (`user-select: none`, `-webkit-touch-callout: none`)
- 창 크기 변경 순간 속도 계산이 튈 수 있음 (입력 모듈, 손대지 말 것)

## 11. 이전 담당이 내린 결정 중 알아 둘 것

- 금관을 도형으로 둔 이유는 이미지 저작권 확인 전이기 때문이다. 사진 대신 직접 그린 도판은 괜찮다.
- 대체 버튼(드래그 못 하는 아이용), 음성, 음소거, 글자 확대는 1차 학교판 범위라 여기서 안 해도 된다. 다만 레이아웃을 잡을 때 그 자리를 막아 두지는 말 것.
- 캐릭터 그림 스타일은 기획자 승인이 필요하다. 먼저 🐸🐍 두 캐릭터 정지 그림만 PR이나 스크린샷으로 보여 주고, 승인 뒤 애니메이션으로 가는 순서를 권한다.
