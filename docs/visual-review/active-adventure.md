# 직접 움직이는 토우 탐험 · 2026-10-22

사용자의 ‘구현해’ 요청으로 영상 참고 제안의 직접 이동·발견·보상 흐름을 기존 발굴 게임에 연결했다.

## 구현

- 5개 탐험길: 두꺼비 점프, 새 비행, 거북 방어, 뱀 좁은 길, 네 친구 협동.
- 각 길에서 빛 조각 3개를 모으고 능력으로 길을 열면 실제 발굴로 이어진다. 유물 정보·생각구름·기존 음성·Suno BGM은 유지한다.
- 금관 뒤 새, 두 번째 유물 뒤 거북, 세 번째 유물 뒤 뱀을 얻는다. 기존 LEVELS와 보호 테스트는 그대로 두고 adventure-progression에서 새 획득 순서를 제공한다.
- 낙하·돌 충돌은 근처 발판에서 재도전. 조각과 열린 길은 유지. 시간 제한 없음.
- 키보드와 두 손가락 이동+능력 입력, 취소·창 전환 시 입력 해제, 일시정지와 재시도.
- 저장 버튼에서만 기록. 기존 별 기록은 읽어서 이어 쓰며 새 탐험도 저장 전 기존 기록을 덮지 않는다. 저장 위치는 선택 구간 시작이다.
- 새 생성 이미지/음원 비용 및 런타임 의존성 없음. 기존 허가된 점토 아트와 직접 그린 Canvas 지형을 사용한다.

## 검증

- `npm test`: 기존 65/65 통과. 지정 보호 파일 및 prototype/tests 변경 없음.
- `node --test checks/adventure-model.test.mjs checks/adventure-save.test.mjs`: 12/12 통과. 다섯 길 모두 실제 이동·능력 입력만으로 통과(위치/결과 강제 변경 없음).
- `node checks/adventure-integration.mjs`: 실제 main/view와 DOM/Canvas 통합 통과. 두 손가락 이동+점프, pointercancel, 정지, Esc 반복 입력, 두꺼비 길 → 실제 금관 발굴·이야기 → 새 합류 → 수동 저장 → 새 비행·도착 → 새 게임의 이전 저장 보존.
- 통합 검사 도구는 tmp/adventure-tools에만 설치: `npm install --prefix tmp/adventure-tools --no-package-lock --no-audit --no-fund jsdom @napi-rs/canvas`. 합성 DOM 크기를 쓰므로 실제 CSS·터치 기기 검증을 대신하지 않는다.
- 최종 독립 코드 검토에서 Esc 반복 키다운의 일시정지 해제 문제 발견. 실패 재현 검사 추가 후 e.repeat 무시로 수정, 재검사 통과.
- 구문 검사 및 git diff --check 통과.

## 브라우저 화면 검증

연결 복구 후 실제 Chrome에서 새 게임 → 도입 이야기 → 두꺼비 탐험, 후반 네 친구 선택 → 새 전환, 일시정지/복귀를 확인했다. PC 기본 화면과 320×568, 390×844, 844×390 크기에서 캐릭터·발판·조작 버튼 배치를 확인했다. 네 친구가 있는 후반 화면도 세로·가로 모두 버튼이 겹치지 않았고 가로 정지 창의 모든 버튼이 보였다. 회전 후 화면이 정상 재배치됐다. [실제 모바일 크기 화면](adventure-mobile.jpg).
