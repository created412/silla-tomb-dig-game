# 모바일 플레이 대응 · 2026-10-22

휴대폰 세로 화면은 토우 능력을 하단에 모으고 발굴판이 화면 가로 폭을 쓰도록 했다. 가로 화면은 낮은 HUD와 하단 능력 버튼을 사용한다. PC의 발굴 영역 여백과 게임 규칙은 유지했다.

- CSS 발굴 영역을 캔버스 배치와 공유한다. 화면 회전·주소창 높이 변화는 ResizeObserver로 다시 계산하며 진행 상태를 초기화하지 않는다.
- 노치·홈 표시줄 안전 여백을 반영하고 브라우저 확대를 허용한다.
- 제목, 준비, 대화, 기억, 질문, 합류, 결과 화면은 버튼까지 스크롤해서 접근할 수 있다.
- 모바일 보스 화면은 목표의 터치 영역을 확보하고, 가로 화면에서는 조작 버튼을 옆에 배치한다.
- 세로 화면의 배경 토우 네 마리는 잘리지 않도록 크기와 간격을 조절한다. 기존 팝업 중복 방지와 음성·BGM은 유지한다.

`checks/mobile-play.html`에서 320×568, 360×640, 390×844, 667×375, 844×390, 768×1024, 1440×900을 검증한다. 실제 앱 소스를 격리된 메모리 저장소와 함께 불러오며, touch PointerEvent로 흙을 문질러 진행 변화를 확인한다. 화면 회전 시 진행 유지, 주요 버튼 접근과 가림 여부, 보스 목표 크기와 단계 성공도 검사한다.

Chrome 내 크기별 검증이며 실제 iOS Safari·Android 기기에서의 직접 검증은 하지 않았다. 보호 대상인 발굴 모델·입력·그리드·대화·HUD 모듈과 prototype/tests는 변경하지 않았다.

검증 결과: 기존 단위 테스트 65개, 보스·음성·음악 테스트 9개, 이야기/겹침 회귀 검사 137개, 크기별 모바일 검사 204개, 가로·세로 전환과 진행 보존 검사 5개 통과.
